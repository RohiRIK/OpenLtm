# Project context items — reference

Besides long-term `memories`, OpenLTM keeps a small per-project state table, `context_items`. Back to the contract: [../SKILL.md](../SKILL.md).

## The four types

| Type | Holds | Lifecycle |
|------|-------|-----------|
| `goal` | The current objective, 1–3 lines | One per project — adding a goal replaces the previous one. |
| `decision` | Project-level architectural or key choices | Permanent; hooks never delete them. |
| `gotcha` | Project-specific warnings, pitfalls, blockers | Permanent; hooks never delete them. |
| `progress` | What each session did | One row per session (deduped by session id), trimmed to the most recent 20. |

## Reading

- `context_items {type?, project?}` — the rows themselves, newest first.
- `context {project?}` — the merged memory restore for a project: global memories with importance ≥ 4 plus up to 15 project-scoped memories with importance ≥ 3.
- SessionStart already injects goal, decisions, gotchas, recent progress, and top memories, so read these tools only when that block is missing or you switched projects mid-session.

`project` defaults to the current project. `/openltm:project register` names or renames the current directory's project.

## Writing

- `context_add {type, content, project?}` — the direct way to set a goal or record a project decision / gotcha.
- `/openltm:project init` — interactive goal seeding for a new project.
- `/openltm:memory learn … --save-context` — stores a memory and mirrors it as a context item.
- `progress` is written by the Stop hook (one row per session); add it by hand only when the user asks you to log something.

Never hand-edit `context-summary.md` or the legacy `context-*.md` files — they are snapshots regenerated by the SessionStart and PreCompact hooks.

## Short-term or long-term?

| Question | Answer → store as |
|----------|-------------------|
| Only true for this project's current state? | `context_add` (goal / decision / gotcha) |
| Useful in future sessions or other projects? | `learn` |
| A temporary note or work log? | `progress` (hooks handle it) |
| A permanent rule that has bitten you more than once? | `learn` with `importance: 5` |

Context items describe *where the project is*; memories describe *what is true and why*. When a project-level gotcha keeps recurring, promote it by calling `learn` with the same content and importance 4–5.
